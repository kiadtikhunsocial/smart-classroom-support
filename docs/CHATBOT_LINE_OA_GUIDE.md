# คู่มือดูแลแชตบอต LINE OA

## ระบบปัจจุบันใช้ AI อะไร

โค้ดเรียก Google Gemini ผ่าน `GEMINI_API_KEY` และ `GEMINI_MODEL` (หรือ Vertex endpoint ที่ปรับแต่งไว้ผ่าน `GEMINI_TUNED_ENDPOINT`) โดยมีเส้นทางสำรองแบบกฎและฐานความรู้เมื่อ AI ใช้งานไม่ได้ หน้า “จัดการแชตบอตและ LINE OA” แสดงสถานะการตั้งค่าโดยไม่แสดงคีย์ การมีคีย์ **ไม่ใช่หลักฐานว่า AI ตอบทุกข้อความ**: ตัวเลือก `ENABLE_GEMINI_CLASSIFIER`, `ENABLE_GEMINI_ORCHESTRATION` และ `ENABLE_GEMINI_NATURAL_REPLIES` ปิดเป็นค่าเริ่มต้น บางงานเรียก Gemini ผ่านขั้นตอนเฉพาะอยู่แล้ว ส่วนประกัน/สถานะงาน/คะแนนต้องมาจากข้อมูลจริง ไม่ให้ AI สร้างเอง

“เทรน” ในหน้าจอนี้หมายถึงปรับฐานความรู้ คำตอบที่ตรวจแล้ว และ prompt สำหรับการเรียกครั้งถัดไป **ไม่ใช่การฝึกน้ำหนักของ Gemini** การฝึกโมเดลจริงเป็นโครงการแยกที่ต้องมีชุดข้อมูล consent, evaluation และ endpoint; ไม่เกิดขึ้นจากการกดเผยแพร่คำตอบ

## เลือกที่ใส่ข้อมูล

| ข้อมูล | ที่แก้ | มีผลเมื่อใด |
| --- | --- | --- |
| คำถามทั่วไป เช่น เวลาให้บริการ | คำถาม–คำตอบ ใน Chatbot Studio | หลังเผยแพร่ ทันทีเมื่อข้อความตรงกับคำถามหรือคำถามทางเลือก |
| อาการและขั้นตอนแก้ปัญหา | ฐานความรู้ | หลังเผยแพร่ ใช้ในคำถามที่จับคู่บทความได้ |
| รหัสอุปกรณ์, Serial, วันสิ้นสุดและรายละเอียดประกันที่เปิดเผยได้ | ทะเบียนอุปกรณ์ หรือ CSV ที่ส่งออกจาก Google Sheets | หลังบันทึก/นำเข้า ลูกค้าต้องให้รหัสก่อนค้น |
| น้ำเสียงและวิธีถามกลับ | คำแนะนำ AI ใน Chatbot Studio | หลังเปิดใช้ มีผลกับคำขอ Gemini ใหม่เฉพาะขั้นตอนที่เปิด AI |
| เจตนารูปแบบใหม่, เชื่อมแหล่งข้อมูลอัตโนมัติ | โค้ดและการทดสอบ | ต้อง deploy |

ห้ามใส่ราคา สถานะชำระเงิน สิทธิ์เคลม หรือสถานะใบงานในคำตอบทั่วไป เพราะจะล้าสมัยและตอบผิดคนได้ ลิงก์แหล่งข้อมูลในคลังเป็น *หลักฐานให้คนตรวจ* ไม่ใช่ระบบอ่านเว็บไซต์อัตโนมัติ หลีกเลี่ยงรหัสผ่านและข้อมูลส่วนบุคคลใน prompt/ตัวอย่าง

## วงจรปรับปรุงซ้ำ

1. เก็บตัวอย่างข้อความที่ตอบผิดโดยลบข้อมูลส่วนบุคคลออก ระบุคำตอบ/เส้นทางที่คาดหวัง
2. เพิ่มคำถามทางเลือกหรือบทความที่มีแหล่งอ้างอิง ตั้งเป็นฉบับร่างก่อน
3. ทดลองในแท็บ “ทดลองถาม” หลายคำสะกดและข้อความกำกวม พรีวิวไม่ส่ง LINE ไม่สร้างใบงาน และไม่เรียก Gemini จึงครอบคลุมเฉพาะชั้นกฎ/ข้อมูล
4. เผยแพร่ แล้วทดลองจริงด้วย LINE บัญชีทดสอบในสภาพแวดล้อมที่อนุญาต ตรวจว่าไม่มีใบงาน/ดีลที่ไม่ตั้งใจ
5. ดูคะแนนและผล “แก้ได้/ยังไม่หาย” บนแท็บผลประเมินเฉพาะ superadmin ปรับทีละจุดแล้วทดสอบซ้ำ

ไม่มีระบบใดรับประกันการเข้าใจข้อความกำกวมทุกบริบท บอตควรถามกลับหนึ่งประเด็นเมื่อไม่มั่นใจ และส่งต่อเจ้าหน้าที่เมื่อข้อมูลไม่พอ

## ประกันและการประเมิน

ผู้ถามประกันต้องส่งรหัสอุปกรณ์หรือ Serial บอตค้นแบบตรงตัวจากทะเบียนและแสดงวันสิ้นสุดกับรายละเอียดประกันที่เจ้าหน้าที่ระบุไว้สำหรับลูกค้า ไม่ยืนยันสิทธิ์เคลมแทนเอกสารผู้ขาย ช่อง “หมายเหตุ” ภายในจะไม่ถูกส่งไป LINE หากรหัสไม่พบ ให้เจ้าหน้าที่ตรวจและเพิ่มอุปกรณ์/Serial ในทะเบียนก่อน แล้วทดลองถามอีกครั้ง

ลูกค้าประเมินบอตด้วย `ประเมินบอท 1–5 แก้ได้` หรือ `ประเมินบอท 1–5 ยังไม่หาย`; รูปแบบเดิม `ประเมินบอท 1–5` ยังใช้ได้แต่จะไม่ทราบผลการแก้ปัญหา เจ้าหน้าที่ประเมินได้ด้วย `ประเมินเจ้าหน้าที่ <เลข Ticket> 1–5` หลังสถานะเป็น “ซ่อมเสร็จ” หรือ “ปิดงาน” และต้องเป็นใบงานที่เชื่อมกับผู้แจ้งรายนั้น ผลประเมินไม่ใช่หลักฐานว่าปัญหาทั้งหมดได้รับการแก้แล้ว

เมื่อ ticket ที่ผูกกับ LINE ID (สร้างในแชตหรือผ่านลิงก์ QR จากแชต) เปลี่ยนเป็น “ซ่อมเสร็จ” ระบบจะส่งคำเชิญประเมินเจ้าหน้าที่ไปยัง LINE ID ต้นทางหนึ่งครั้ง หากส่งไม่สำเร็จและมีการปิดงานภายหลัง ระบบลองส่งอีกครั้ง ไม่ใช้ชื่อหรือเบอร์โทรมาคาดเดาผู้รับ ส่วน ticket ที่สร้างผ่านหน้า QR โดยไม่ได้ผูก LINE ID จะไม่ส่ง LINE push อัตโนมัติ ผู้ดูแลบทบาท owner และบัญชี superadmin ที่กำหนดดูคะแนนในหน้า “ผลประเมินลูกค้า” ของพื้นที่เจ้าหน้าที่ได้

กรณีบอตแนะนำวิธีแก้เบื้องต้น: หากลูกค้าตอบว่า “หายแล้ว” บอตจะชวนประเมินบอต 1–5 โดยไม่สร้าง Ticket; หากตอบว่า “ยังไม่หาย” บอตจะชวนประเมินบอตพร้อมส่งลิงก์ฟอร์มสแกน QR ที่ผูกกับ LINE ID จาก webhook ที่ตรวจลายเซ็นแล้ว ลิงก์มีโทเคนสุ่มใน URL fragment (ไม่ส่งไปกับคำขอหน้าเว็บ) ใช้ได้ครั้งเดียวภายใน 30 นาที ฐานข้อมูลเก็บเฉพาะแฮชและไม่บันทึกโทเคนลงประวัติแชต ให้เปิดลิงก์แล้วกดสแกน QR **ในหน้านั้น** ไม่ใช่เปิด QR ผ่านแอปกล้องเป็นหน้าใหม่ มิฉะนั้นโทเคนอาจไม่ถูกส่งต่อ หลังส่งฟอร์ม backend จะบันทึก Ticket และผูก LINE ID ในธุรกรรมเดียวกัน จากนั้น push เลข Ticket กลับแชต; หาก LINE ส่งไม่สำเร็จ ใบงานยังคงถูกสร้างและหน้าเว็บจะแสดงเลขให้จด ผู้ใช้พิมพ์ “ติดตาม” หรือ “รายละเอียดใบงาน” ใน LINE เพื่ออ่านสถานะ/รายละเอียดปัจจุบันจากฐานข้อมูลได้เฉพาะใบงานที่ผูกกับ LINE ID นี้เท่านั้น ไม่เดาจากชื่อ เบอร์โทร หรือเลข Ticket ของผู้อื่น

การประเมินเจ้าหน้าที่เริ่มเมื่อเจ้าหน้าที่เปลี่ยนสถานะใบงานเป็น “ซ่อมเสร็จ” (resolved) ระบบเชิญให้ลูกค้าตรวจผลและให้คะแนนจาก LINE; หลังปิดงาน (closed) ยังประเมินหรือแก้คะแนนเดิมได้ ถ้าใบงานยังไม่อยู่สองสถานะนี้จะไม่รับคะแนนเจ้าหน้าที่ ส่วนใบงานเก่าที่ไม่ได้ผูก LINE ID จะไม่ได้รับ push อัตโนมัติและไม่แสดงรายละเอียดส่วนตัวผ่านบอต

ฟอร์มแจ้งซ่อมจาก QR มีปุ่มขออนุญาตตำแหน่ง ลูกค้าจะส่งหรือไม่ส่งก็ได้ หากอนุญาต ระบบบันทึกพิกัดที่เบราว์เซอร์รายงานไว้ใน ticket พร้อมลิงก์แผนที่สำหรับเจ้าหน้าที่ พิกัดอาจคลาดเคลื่อนหรือถูกปลอมได้ จึงไม่ควรถือเป็นหลักฐานยืนยันว่าลูกค้าสแกนอยู่หน้าอุปกรณ์จริง

## ตั้งค่าก่อนใช้งานจริง

Render ต้องมี `GEMINI_API_KEY` และเลือก `GEMINI_MODEL` ที่บัญชีใช้งานได้ ตรวจสถานะในหน้า Studio แล้วลอง LINE จริงหนึ่งข้อความ หากต้องเปิด feature flag AI ให้เปิดทีละตัว ทดสอบคำถามซ่อม/สินค้า/ข้อความกำกวมและดู latency/ค่าใช้จ่ายก่อน ไม่ควรเปิดทุก flag พร้อมกันใน production และไม่ควรส่งคีย์ทางแชต
